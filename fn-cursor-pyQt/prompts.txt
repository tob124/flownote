现在进入核心的 AI 处理环节。我们要启动一个后台线程默默工作，并且彻底锁死 AI 乱建分类的幻觉。

1. **新建 `ai_worker.py`：**
   - 引入 `requests`，编写 `call_llm(provider, api_key, prompt, content)`。
   - 编写 `safe_parse_json(text)`：用正则提取 `{}` 内容并 `json.loads`。

2. **后台队列线程 (`AIQueueThread` 继承自 `QThread`)：**
   - 无限循环：`while True: ... time.sleep(15)`。
   - 扫描 `/notes` 寻找最多 3 条 `pending` 的笔记。
   - 重点防撞：将这几条 JSON 的 `ai_status` 改为 `processing` 并写入硬盘。
   - **Prompt 极严约束：** 动态读取 config 里的 `categories` 列表。在 Prompt 中严厉警告大模型：“你必须且只能从以下列表中选择 category：{categories}。绝不准创造新分类！如果你觉得都不符合，输出 'Inbox'”。
   - 解析 LLM 结果：如果在返回的 JSON 中，category 不在允许列表中，Python 代码强制将其改为 'Inbox'。
   - 成功则更新字段，设为 `done` 并落盘。失败则 `retry_count += 1`，>= 3 次设为 `failed`。
   - 发射 `note_updated` 信号给主线程。

3. **UI 联动：**
   - 在主窗口启动 `AIQueueThread`。接收到 `note_updated` 信号时，重新读取列表刷新 UI。
   - 强制约束：在 UI 渲染笔记卡片时，如果状态是 `done`，其对应的 QTextEdit 必须设为 `setReadOnly(True)`。

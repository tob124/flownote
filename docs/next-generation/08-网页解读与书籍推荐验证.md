# 两个高弹性能力的设计研究：网页解读与书籍推荐

R3 调研稿，2026-09-23。此处定义待验证的用户体验和判定门槛，不授权代码施工或新增付费服务。用户本轮选择“持续推进目标与复盘”为首要方向：网页和书籍只有在帮助一个具体议题/目标时才值得进入核心流程。原 R2 的 T06 网页提取是底层资料采集，不能代替“网页解读”；R2 尚未为书籍推荐立项。

## 1. 先区别五种经常被混称为“解读”的工作

| 能力 | 用户实际要回答 | 输入 | 成功标志 |
|---|---|---|---|
| 收藏 | 我以后能找到它吗 | URL、个人简短原因 | 即使远端失败仍保存链接与我的记录 |
| 提取 | 这页真实写了什么 | 页面正文快照 | 原文可核对、目录/广告不过多混入、范围明确 |
| 理解 | 作者核心论点是什么 | 已核对片段 | 论点、依据、限制可回到原文；不把作者观点写成事实 |
| 联系 | 它对我的目标/旧看法有何新增 | 网页＋用户选定目标/笔记 | 显示新增/重复/冲突或“暂无明显关系”，引用两边 |
| 行动 | 我需要做什么 | 用户目标与上述比较 | 提议一个可选择的阅读/验证/实践步骤；用户决定是否记录 |

绝不在“只抓到网页标题”时提供“全文解读”。提取与理解是两次不同质量检查。带出处也不等于解释正确；用户能随时打开原文并修正截取范围。

## 2. 网页解读建议流程

**触发：** 粘贴 URL 即刻保留书签和可选的“为什么保存”；后台按 R2 的安全规则取得快照，不自动发 DeepSeek。完成后显示“正文可核对 / 正文疑似不完整 / 仅链接”三种状态，而不是只有成功/失败。用户需要时选择“速读”或“对照当前目标/一条笔记”；后者先明确使用哪一份个人材料。

**内容快照：** 保存原 URL、最终 URL、抓取时间、标题、作者/发布日期（仅在页面可辨认时）、提取文本、提取器版本、正文指纹、段落定位和诊断信息。抓取时间不等于文章发表时间。改版网页保留旧快照；重抓得到新版本，不能覆盖用户对旧版的高亮或批注。

**质量诊断：** 比较原始 HTML 的候选正文区、Readability 输出、标题一致性、正文长度、段落重复度、导航/广告特征、是否明显“登录后可见”、语言与字符集。诊断只是信号，不自动证明完整。很短的正文可能就是短公告，不以固定字数宣布失败；较长也可能全是导航。给用户“查看提取原文 / 换成我粘贴的正文 / 仅保存链接”的恢复路径。

**速读输出：** 用“作者在主张什么”“文中给了什么依据”“哪些是文章没有回答的”“值得回原文看的段落”四栏中的适用部分，宁可少而准。每个事实性短句绑定本次快照段落；“依据不足”单独说明。不能由页面内容触发工具调用或生成伪造的外部事实。长文先显示选入的段落及未覆盖范围，不说“已读全文”。

**对照输出：** 明确选定一个议题/目标和本地材料范围；输出“支持/补充”“有张力”“还缺什么”三类候选，允许全部为空。每条要有网页片段及个人资料片段两端出处，用户可标记相关/不相关。网页中的主张属于作者；个人记录属于用户；模型推断单独标记。对目标的下一步只能是建议，由用户确认后写入目标记录。

**异常：** 公众号或登录站拿不到正文，停在仅链接/用户粘贴，不伪装成功；原网页消失时仍能看已保存快照，显示采集时点；解析混入脚注/评论时可手动排除段落重新解读；用户不愿将私人笔记传给模型时只做本地对照候选或不运行。R2 的 SSRF、重定向、大小限制仍有效。

这比“保存时自动生成一段通用摘要”多一步用户选择，却减少无用调用。类似产品的[Readwise 解析说明](https://docs.readwise.io/reader/docs/faqs/parsing)承认公开网页不可百分百提取正确，且浏览器扩展能取得比裸 URL 更完整的页面；这支持保留手动正文/未来扩展入口，但不意味着本轮必须开发浏览器扩展。[Readwise 的文段与文档级提问](https://docs.readwise.io/reader/guides/ghostreader/overview)支持按用户关注点决定解读范围的设计参考。

### 2.1 网页验证清单

用公开页面构造至少30个样本：中/英文、正常静态文章、长文、很短公告、表格/图片为主、动态加载、付费墙、登录墙、重定向、多页、失效链接、标题党、评论/广告密集、同URL改版。记录每个样本保存状态、提取正文范围、错误诊断、用户修正用时和模型实际请求数。对10个有文章主张的样本人工逐句核对速读；对10个与目标相关/无关混合样本评估“新增/重复/冲突”的判别以及用户是否真的采纳。未能稳定提取时，T06只交付安全收藏与手动正文，不宣称“智能网页解读”。

建议硬门槛：书签零丢失；任何无法定位到本次快照的事实性结论不作为可信结果发布；未提取到正文的页面不触发付费摘要；若用户对照现有手动阅读没有节省时间或发现有用新信息，则从正式版撤下自动解读入口。具体质量阈值须在样本和用户评估后锁定，不凭空宣布“90%准确”。

## 3. 书籍推荐首先是什么问题

需求应写成“为了推进**目标/问题 X**，接下来读什么能补足我当前认知的缺口？”而不是“根据我所有笔记随机推荐好书”。书目存在、版本存在、书对议题有帮助，是三个不同的判断：书目元数据可由目录核实；“对我有帮助”必须结合用户目标和已读情况；模型不能凭书名声称知道一本书的全部论证。

两种顺序：

1. **库内回看：** 先找用户已记录、想读或已读但尚未运用的书与摘录；能提出“先重读你标注过的这一章”时，不急着推荐新购买。未记录阅读状态则显示未知，不猜测。
2. **外部发现：** 由用户明确点击“找新书”，选定议题、语言和“不想看到/已读”反馈；只向外部书目服务发送搜索词，不发送私人笔记全文。先得到真实书目候选，再由本地规则与可选模型为已核验候选写短理由。模型不得生成目录中不存在的书作为商品卡。

每张推荐卡至少有：书名、作者、语言、可核对的目录链接、工作/版本标识（有则显示）、推荐理由所依的用户目标/笔记、当前已知与未知、是否已读/忽略。ISBN 只在目录返回并核对相应版本时展示；同名不同作者、同作品不同译本不得糊成一本。出版年、译者、封面、购买/可读性信息缺失就留空，不由模型补写。没有可靠候选时给“换关键词/手动录入想读书”而不是编造三本。

[Open Library Search API](https://openlibrary.org/dev/docs/api/search)可返回作品、版本、语言、作者等，但文档也说明若干字段的结构并非完全稳定；其[Books API说明](https://openlibrary.org/dev/docs/api/books)区分 Work 与 Edition。它是候选目录，尚未验证中文书目覆盖和地区可用性。[Google Books API](https://developers.google.com/books/docs/v1/using)提供卷册检索，但公开数据请求也需要 API key；不能默认替用户开通 Google 项目或把新凭据要求写成正式版前提。现阶段不抓取书商网页，也不宣称可获得书全文或实时价格。

### 3.1 候选排序是可解释的选择，不是“AI 热榜”

先按确切书目身份去重，过滤用户已读/忽略的版本；再看与当前问题的直接相关性、语言可读性、作者/主题多样性、是否与库内已有书重复。结果控制在少量候选，展示“适合解决什么”和“可能不适合什么”。评分只是排序辅助手段，具体权重需用用户标注样本调试；不把“评分高”作为读书理由。若模型只见书名/简介，卡片必须写“根据书目简介推断”，不能写“本书第X章论证……”。

可提供“不相关 / 已读 / 暂不读 / 想读 / 读完后有帮助”反馈。负反馈只影响后续候选，不能被当作用户永久偏好。想读只是用户确认的跟进事项；每周目标回看可以询问是否仍有需要，用户可关闭。不要由软件擅自推送购买链接、书商返佣或“必须读”的命令式建议。

### 3.2 推荐验证清单

先建不少于30条真实且可公开核对的书目夹具，其中中文与译本至少占三分之二，包含同名书、同作品多译本、绝版/缺字段、用户已读、无匹配、书目服务超时。逐个记录 Open Library 目录命中率、身份正确率、中文版本/作者匹配率；不足时不得宣称“中文书籍推荐已可用”，先保留库内回看和手动想读清单。若未来评估 Google Books，先计算密钥配置和维护成本，不因英文样本好就默认接入。

效用评估使用用户自选的5–10个真实目标/问题，与“自己搜索书名和书单”对照。问用户候选中哪本愿意看、为什么、是否重复/偏题、是否愿在下一次相同问题继续使用。只有“存在且相关”还不够；应观察至少一次读后反馈，确认是否帮助目标推进。样本数量是发现问题的起点，不是已完成测试或统计结论。

## 4. 与 R2 施工包的关系

- T06 的安全收藏、来源快照和手动正文路径仍是必要地基。本文的“速读/对照目标”是通过验证后才可增加的任务，不混进 T06 验收。
- 05 的“推荐相关资料”当前只按知识库名称/说明做本地搜索，是候选召回，不等于本研究的书籍推荐，也不能宣传为懂用户长期目标。
- T09/T17 的引用问答可复用来源校验；网页解读还需“作者观点 vs 我”的角色分离和正文完整性判断。
- 书籍推荐是 R3 候选，**没有施工编号**；目录覆盖、存在性与真实效用未验证前，不要让 Sol 自行加接口和推荐页面。
- 成本按用户动作计；普通收藏和库内候选为零模型调用。速读或对照经用户触发才可发送选定内容。请求上限、缓存键与故障恢复须在 G4 决策卡中按实际样本确定，沿用05的日预算硬限制。

# 思想伙伴交付与联网复核

日期：2026-09-28。本文记录本轮实现与实测，取代旧规划中“目标、成果、主题知识库为产品主线”的方向。历史规划保留供追溯，不应继续按旧任务表扩建功能。

## 当前产品范围

主线是记录 → 回应 → Dream 深入讨论与外部知识。保留 Notes、Wiki、Dream；停用目标、成果、主题知识库的导航和运行接口，保留原文件，并提供设置中的逐文件导出。没有引入语义检索、向量库、本地模型或新 AI 供应商。

已实现统一创建时间解释与排序、独立新编号、本地先保存、后台 AI 队列、过滤后的定位入口，以及目录切换后的旧结果隔离。简评覆盖普通生活判断，不限于思想性笔记；正文版本变化会使旧回应和旧纠正失效。

纠正建议需要可核对的正文依据。接纳后修改相应 Wiki，保存修改前后版本，并保留已接纳的观点修正；否决不改 Wiki，也不改原笔记。找不到足够证据时仍可评价，但不会提供可写入 Wiki 的纠正按钮。

## DeepSeek 原生搜索的结论

**可以继续作为默认的来源发现能力，但不能直接当作全文读取和事实核查服务。**

官方实现使用 Anthropic 兼容 Messages 接口，依赖结构化 `web_search_tool_result`；没有独立轻量搜索端点。来源摘要需要引用块中的 `cited_text`，并非每次都有。实现仅接受结构化来源，不把模型自己写出的链接当作检索结果。

参考：[DeepSeek 官方搜索适配说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/README.md)。

本机复现了实际原因：公开域名被 TUN 代理解析为 `198.18.*` 地址，原正文读取器将其全部当作非公网地址拒绝。这与 DeepSeek 搜索是否成功是两个问题。修复保留公网限制：只有域名解析结果全部为代理占位地址时，才通过 Cloudflare DNS-over-HTTPS 查询该域名的真实 A 记录，验证地址为公网，然后固定该地址建立连接。不会向 DNS 服务发送笔记、搜索词或密钥；普通公网 DNS 情况不使用额外解析器。私网、环回、地址字面量、非 HTTP(S)、危险端口和重定向目标仍受检查。

同机实测 NHS 饮食资料读取到约 11,305 字符，普林斯顿大学出版社首页约 5,041 字符。API 与两站点通过 Node 和 Chromium 均可连通，因此未因本次故障迁移所有网络请求到另一套实现。

另外修复了三类工程问题：

- 保留每个来源的读取状态和失败原因，区分拒绝访问、超时、下载文件、未尝试与已读正文。
- 优先查询候选书籍及作者原名，跨查询分配读取机会；PDF/Office 文件不占用静态网页读取预算。不绕过登录、付费墙或网站访问限制。
- 深入分析出现无最终正文的情况时，提供可重试的错误；提高有思考输出的限额，记录失败响应的实际用量。重试保留完成的搜索、材料整理和页面读取。

客户端最多发起三次搜索请求，每个请求发送 `max_uses: 2`，最多读取六个网页；使用服务端报告的实际用量停止后续搜索。**服务端返回的搜索计数并不总与请求的使用上限一致**：一次真实流程报告 11 次，后续流程报告 4 次。不能将请求参数宣传为绝对收费上限。已如实记录返回计数，没有自动切换其他收费供应商。

## UI 与操作

沿用温润纸感。使用已安装 Vercel 的 React 检查与 agent-browser 验证技能，不为本次改版引入完整聊天组件框架。

- 列表保留简短预览与评价、找观点、追问入口。
- 展开后打开独立阅读窗，原笔记留在背景；支持 Escape 关闭和原生模态焦点限制。
- “回应 / 延伸阅读 / 继续讨论”分开呈现，支持键盘切换页签。
- 推荐先呈现对应问题、观点和为什么有帮助；边界、阅读位置、证据细节按需展开。
- 失败来源可打开原网页；深入分析可重试资料核查，复用已完成搜索，但新的分析生成仍会产生模型用量。
- 用量收进“本次生成记录”，不占据主要阅读区域。

## 验证证据与边界

截至本次记录：类型检查、生产构建、59 项自动化测试通过。开发版 Electron 完整流程验证通过：离线保存立即可见、混合旧编号、清除筛选定位、后台分类、简评、追问、接纳后更新 Wiki、Dream、重启恢复、无页面异常。浏览器工具实际点击了追问入口并检查模态窗与页签；公开样例的新版阅读界面已截图检查。

真实 API 测试使用独立 `.e2e` 数据目录与公开样例，密钥由环境传入测试进程，未写入测试配置或文档。真实荐书流程取得来源正文并完成推荐；一次得到《决断力》的馆藏内容提要支持，准确降为二手依据。普通“睡前要多喝牛奶”的核查因资料不足没有产生可写入 Wiki 的纠正。**这证明链路可以运行，也证明应保留降级；不代表全部荐书质量已经通过产品验收。**

自动化的接纳流程使用明确标记的测试证据，验证的是数据变更和确认边界，不冒充真实健康证据。旧模块导出通过字节与 SHA-256 检查。代理解析测试覆盖替代解析后仍返回内网地址、混合公网/内网地址，以及普通 DNS 不额外发起查询。

可重复的检查：

```text
npm run typecheck
npm run test:run
npm run test:e2e
```

`scripts/verify-live-thinking.mjs` 会使用已配置的 DeepSeek 密钥产生真实用量，应明确需要真实验证时才运行。`scripts/verify-interface.mjs <.e2e 中的测试目录>` 仅展示已有公开样例，关闭测试配置中的 AI 自动处理。

## 产品经理内容验收样本

| 输入 | 预期体验 / 不应出现的行为 |
|---|---|
| 睡前要多喝牛奶 | 客观讨论条件；未经核查不应给确定剂量或强制写入 Wiki 的纠正 |
| 明天买牛奶、取快递 | 允许不评论，不应凑一份书单 |
| 做重要决定也应该越快越好 | 区分快慢与质量，指出可逆性、经验反馈等条件；推荐观点必须与这些条件直接相关 |
| 我最近反复修改计划却没有行动 | 可以给暂定解释及小建议，不推断人格或强行心理诊断 |
| 只要努力就一定成功 | 认真回应控制范围、环境和反馈，而非固定表扬或机械反驳 |
| 记录一个自己还没想清楚的问题 | 先给有理由的暂定回答，允许就地追问，不只列问题 |
| 同名书或未核实中译本 | 明示书目尚未核实，不编造译者、章节、页码 |
| 已读过的推荐再次出现 | 必须有新的具体用途；“不相关”反馈应影响后续推荐 |

来源归属和引文准确性仍是硬门槛；“是否真的带来新认识”由用户试用验收。搜索覆盖、站点访问限制与模型判断误差仍存在，不能以生成成功替代这一验收。

# 竞品调研与产品取舍

## 1. 核心判断

FlowNote 值得借鉴的是“低摩擦采集、保留来源、自动整理、按需调用知识”的连续体验。现有 Wiki 和 Dream 已有自己的价值，不必为了模仿竞品而更换主界面、重写技术栈或购买完整云服务。

Get 官方文档目前以“得到大脑（原 Get 笔记）”呈现，功能范围已经超出早期语音笔记。本报告继续用 Get 称呼它，避免将不同时间的产品形态混为一谈。[官方入口](https://doc.biji.com/)

## 2. 能力地图（R2：完整Windows版本）

下表“Get 能力”是官方资料声明，不表示各平台、套餐、地区均完全一致，也不代表实际效果已经由本次调研测量。

| 能力组 | Get 的公开能力 | FlowNote 现状 | 升级决定 |
|---|---|---|---|
| 快速文字记录 | 随手记录、AI 整理 | 已有快速输入、自动标题/摘要/分类/标签 | 保留现有操作，补来源和状态 |
| 语音与会议 | 速记、会议/课堂、内录、音视频导入、声纹/词库 | 只有依赖浏览器接口的轻量语音入口 | 用户明确排除本轮开发 |
| 图片与拍书 | 图片文字/内容理解、拍书 | 附件保存、预览、缺失补齐 | 首批：OCR、可搜索文本、原图对照 |
| 链接收藏 | 图文和部分视频平台链接解析 | 没有正文采集链路 | 首批：公开网页与粘贴正文；不承诺任意平台 |
| 文件知识库 | PDF、Word、PPT 入库 | 附件不等于可检索内容 | 图片先行；正式版包含 PDF/DOCX，PPT 暂缓 |
| 自动整理 | 标签、分类等组织方式 | 已有固定 category 与标签 | 延续；不为了“均衡”强制误分类 |
| 主题知识库 | 创建多个库、加入已有笔记 | 主要按分类与月份形成 Wiki | 正式版：完整主题知识库，引用笔记、不复制原文 |
| AI 搜索/问答 | 自然语言调用知识 | 标题/正文子串搜索，无知识问答 | 首批：本地召回、片段引用、回答落地 |
| 记忆库 | 汇聚多种来源、跨时间联系、个人档案 | 原笔记、Wiki、Dream 分散 | 统一检索，暂不建立自动“人格档案” |

| 润色 | 改善表达 | 已有轻度润色 | 保留，不能静默改写已保存原文 |
| 创作与成果 | 从记录产出文章等成果并归档 | 已有 Markdown Wiki/报告 | 正式版：素材→提纲→草稿→版本，Markdown导出 |
| 自动订阅 | 博主/直播内容自动采集 | 无 | 暂缓：平台变化与持续维护成本高 |
| 多端 | 手机、网页及其他客户端 | Electron 桌面与文件中转 | Windows 主端，移动可选采集端 |
| 分享/团队 | 知识库分享、团队管理 | 个人文件库 | 不建设团队权限与公共分享 |
| 开放平台 | API、CLI、MCP/技能入口 | Electron IPC、本地 inbox | 先稳定内部接口；开放接口延后 |
| 专用硬件 | 录音卡及关联工作流 | 无 | 不做 |

## 4. 应吸收的设计原则

1. **保存先成功，AI 随后工作。** 网络失败不影响留下原文、图片和链接；任务失败可重试，已有资料仍能浏览。
2. **从入口直接完成常见任务。** 在现有输入区提供“写笔记 / 存链接 / 图片”，无需先决定分类、文件夹和知识库。
3. **原始资料与 AI 产物分层。** 用户想法、外部文章、OCR 文字、AI 评论不能混成一段无法辨认来源的正文。
4. **每个重要结论能够返回出处。** 搜索和问答应支持从答案跳到笔记、网页快照或图片识别文字；不满足于展示一个文件名。
5. **组织方式服务找回。** category 延续 Wiki 的组织习惯，主题集合承载跨分类问题；不要求各类别笔记数量均匀。
6. **主动能力要有成本边界。** 保留自动分类与 Wiki；发芽、评论、图片语义理解默认手动触发，不自动为每条资料执行整套 AI 工序。
7. **减少反复整理同一内容。** 已提取正文和图片文字缓存复用；问答只读相关片段；Wiki 合并一批新增笔记。

以上为结合竞品与工程提出的产品设计判断，不是对 Get 内部算法的推断。

## 5. 完整升级与分阶段范围

Alpha先实现截图/公开文章保存、全文检索和带引用回答。Windows正式版继续交付主题知识库、限定范围的有限轮追问、关联/反思/点评、Dream覆盖与引用、带版本的成果工作台，以及支撑这些流程的PDF/DOCX解析、收藏/筛选/明确选中项批量操作和Markdown编辑。

这次对标力度主要体现在知识如何被反复使用：同一材料能进入不同主题、支持追问、产生可核对的启发，并形成有来源的作品。不是只把更多按钮堆在快速输入框里。完整交互与成本边界见05，施工依赖见06。

继续排除或暂缓：语音全链、自动订阅社交媒体、登录态爬虫、评论区完整备份、全文向量化、知识图谱、公共知识库、团队协作、书目自动推荐、PPT/长图生成与任意块式富文本编辑。移动端仅可选采集，不移植完整桌面知识工作区。

## 6. 历史 TODO 的处理

- Git/GitHub已配置，不重复实施。
- 附件打开已有UI和shell.openPath路径，核查图片入口与错误反馈，不当从零新增。
- Wiki搜索纳入统一检索，分类队列纳入可靠任务与同Wiki串行合并。
- 收藏、组合筛选、明确选中项批量操作、Markdown编辑纳入正式版，服务资料管理和成果创作；不增加全库全选、按首字母排序、批量移动category。
- 图标、书目推荐继续单独排期；编辑器采用Markdown源码/预览，不复制完整Notion类产品。
- 分类不均衡优先通过跨类别主题知识库缓解；本次未分析真实笔记分布，不擅自重分类旧库。

## 7. 对标不是全量复制

Get的记忆汇聚、问答和成果版本提供方向；FlowNote选用本地文件、用户自带API和坚果云。语音、团队、硬件和订阅属于Get的重要组成，但与用户本次明确边界不一致，必须排除。选择更强的施工模型改变的是工程实施能力，不改变运行时供应商和成本约束。

# R3 计划审计与轻量检索决策

2026-09-23。仅更新研究和施工文档，未修改业务代码或安装依赖。用户决定：**本轮不做语义检索**；未来施工使用 **GPT-6-Sol**，可用 high 或 xhigh 思考强度。运行中的 FlowNote 仍按既定边界使用 DeepSeek/PaddleOCR。审计对象为现有01–09规划、package.json 和关键界面/搜索入口。

## 已发现并修正的三处明显缺陷

| 缺陷 | 原计划的具体表现 | 修正后的规则 |
|---|---|---|
| 语义检索有“后门” | 02写着同义召回不足可另评估本地 embedding，05也保留独立提案；容易把重型包重新带入计划 | 本轮明确排除 embedding 模型、向量库、ANN与专用运行时；同义词漏召回是可见、可评测的关键词检索局限，不自动触发新依赖 |
| 检索包被当成前提 | T07指定 MiniSearch 与倒排索引，未先测现有搜索的真实规模/性能 | 先扩展现有关键词/字段搜索并跑1千/1万条合成数据；只有性能不达标才评估轻量倒排索引。MiniSearch是零外部依赖的全文检索库，**并非语义检索包**，也不是必装项 |
| 验证门槛有循环依赖 | R3的 G2要求原型/效用证据，但文字容易理解成 G4之前不能做任何原型；跨数周真实试用又被放得过早 | G0–G3允许纸面、可点击或可丢弃的受限原型；G4决定是否正式施工；G5在有限实现后跨数周试用并决定能否宣称长期价值 |

[MiniSearch官方项目](https://github.com/lucaong/minisearch)明确是内存型全文检索库，支持精确、前缀与模糊词匹配，零外部依赖。它仍需真实内存、构建时间与安装体量评估，不能因为名字“小”就不测。[Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)是运行时已有分词接口，不需下载中文模型。现有package.json没有 MiniSearch、embedding或向量数据库依赖；本轮未增删包。package-lock 中出现的 `http-cache-semantics` 处理 HTTP 缓存语义，与向量/语义检索无关。

## 搜索和问答的明确边界

- 普通搜索只按用户输入的字词、标题、标签、正文、来源范围和日期工作；零模型调用。可有前缀/错字容忍，但不宣称理解“意思相近”。
- QA只对本地关键词找到、用户手选或上一轮已核验的来源作引用回答。无证据时告知当前范围与词，提示改词/选资料，不能自动扩大全库、联网或调用模型改写搜索词。
- 追问可复用上一轮来源并显示范围；若“它”指谁不明，要求用户明确，而不引入独立语义检索阶段。
- 同义问法留在评测集用于暴露限制，不能因这一组测试得分低而擅自装 embedding。时间变化、冲突和未检索到的材料也要显式呈现不确定性。
- 先测现有搜索在合成规模的热/冷查询、更新、内存和安装包体积；轻量索引只是必要时的性能优化。性能数据未测前，文档里的 P95目标是目标，不是当前能力。

## GPT-6-Sol 的交接原则

可选 high 或 xhigh 由用户按任务复杂度选择。建议普通单模块包用 high，数据迁移、跨模块状态机、崩溃恢复和集成冲突可选 xhigh；这是工作安排建议，不是模型能力保证。两种强度均按同一数据安全、真实验收与成本约束执行。文档中旧 GPT-5.6-Sol 称谓已经统一替换，06的可复制指令也已更新。

## 重排正式施工前还要补的缺口

R2 的25个任务包中**没有 Goal/Commitment/Decision/CheckIn 的正式实现包**，而用户现在把目标推进与复盘列为首位。因此05/06不能直接拿来做最终3.0路线。09给出了最小对象和体验，G2先验证该旅程，G4再为其分配施工任务号、依赖、迁移与验收。产品顺序建议：

1. 先保留可靠存储、任务与来源边界，测量搜索基线；可在假数据上制作目标/复盘原型。
2. 目标对象与用户确认的决定/回看流程成为正式产品主线；关键词搜索和来源证据为它服务。
3. 经验证有效后，再接 OCR/网页对照、Dream中的变化提示、洞察与成果；书籍推荐保持独立候选。
4. UI设计围绕“快速记录、阅读证据、做决定、回看变化”四个关键情境，而不是按旧菜单数量增加页面。

已在06增加三个 R3 主线候选插入点及最早依赖，消除“目标为主线但任务图无处落脚”的规划缺口。它们尚未编号或获 G4 批准，R2 仍只作技术草案；需要 G4 决策卡和更新后的05/06才能正式交付 Sol。

## 仍未实测的风险

用户真实库的规模、基线查询速度、内存与打包体积尚未量过；网页提取、图书目录中文覆盖、DeepSeek 回答质量、跨数周目标回看均未实测。审计没有发现必须先阻止 UI/UX 调研的设计矛盾，因此可并行研究界面，但不能把视觉稿当作上述能力已验证的证据。

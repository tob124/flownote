# 多端与坚果云方案

R2说明：本文件对应06中的可选T23/T24，Windows正式版范围扩大不改变本文件的移动端边界。`主题/会话/成果`仅在Windows实施，移动端仍只采集。

## 1. 结论与约束

推荐“共享采集界面与数据协议，分别适配平台能力”：Windows继续Electron；Android试验Capacitor；原生鸿蒙试验ArkWeb薄壳。移动端只负责采集，不运行Wiki/Dream，不修改正式Note/Wiki文件。

“一次开发”在本工程中可以实现业务规则、采集UI与协议的复用，不能理解为现有Electron安装包一键转换为APK/HAP。Node文件读写、Electron IPC、自定义文件协议、系统文件选择和凭据存储都需要适配。

用户已接受：若移动端太难，仅交付Windows。因此不为了尚未验证的移动端能力先重写稳定桌面应用。

## 2. 技术路线比较

## 3. 坚果云的职责

Windows继续通过坚果云桌面客户端同步本地sync_dir，FlowNote不再同时对该目录运行另一套WebDAV同步。手机通过独立应用密码访问WebDAV，仅上传采集包、读取对应回执。

坚果云官方说明了第三方应用密码和WebDAV的频率/目录返回限制；批量列举不能假定一次返回完整文件列表。具体额度以账户实际结果为准。不能将云盘的本地rename等同于跨设备原子事务或锁。[授权与限制](https://help.jianguoyun.com/?p=2064) · [同步与冲突说明](https://help.jianguoyun.com/?cat=9)

设计避开最困难的双向编辑：手机不更新notes/wikis，不删除桌面知识库，多个设备上传各自唯一命名的新采集。Windows是唯一正式入库者，回执为追加式记录。

## 4. Capture协议 v1

### 4.1 数据形状

每次点击保存创建一个UUID captureId和永久deviceId。采集包不可变；修改未上传草稿可以覆盖本机草稿，一旦开始上传，修改内容就创建新的captureId，不能复用同名包覆盖远端。

```text
captures/<deviceId>/<YYYY-MM>/<captureId>/
  assets/<assetId>.<ext>
  manifest.json
  ready.json

receipts/<deviceId>/<captureId>.json
```

manifest字段：`schema_version:1`、`capture_id`、`device_id`、`created_at_ms`、`kind:text|image|url`、`text`、`url?`、`assets[{id,name,relative_path,size,sha256}]`。text是用户记录/批注，URL正文由Windows提取；首版不在手机执行OCR或调用DeepSeek。

ready字段：`manifest_sha256`。回执字段：`capture_id`、`status:imported|rejected`、`note_id?`、`imported_at_ms?`、`error?`。附件不齐或云盘尚未同步完成不写rejected，留待重试；协议版本不支持/清单持续校验失败才报告需处理。

手机先持久化完整本机包，再上传assets、manifest，最后上传ready。每个写入失败可重试。Windows只有见到ready且清单/附件hash全部通过，才进入导入事务；云盘把ready先同步下来也不会导致提前入库。

### 4.2 幂等、删除与故障

- Windows以capture_id去重，先查持久化回执，再查Note.capture_id。已入库不再次生成笔记或AI任务。
- 正式Note与Source保存完成后写回执。崩溃发生在Note与回执之间时通过Note.capture_id恢复；不能“先回执、后写笔记”。
- 每条入库记录包含capture_id；回执不因用户删笔记而删除，避免旧包重放复活已删除记录。
- 路径须在包目录内；拒绝绝对路径、`..`和超限附件。首版单包最多10张图片，单张20MiB、总计50MiB。
- 网络提交成功但响应丢失时，手机校验远端同名对象是否完整，一致则继续；同captureId清单hash冲突停止并显示错误，不覆盖。
- 采集包上传后本机至少保留至收到回执。首版不自动远端清理；提供已入库包占用统计和手动清理入口，明确回执必须保留。
- Windows离线时手机显示“已上传，等待电脑入库”；只有回执imported才能显示“已入库”。
- 素材包不改写共享inbox.txt，避免手机追加与Windows清空之间的竞争。旧inbox入口继续为现有习惯服务。

### 4.3 同步节奏

手机前台启动、点击同步、刚保存时触发队列；在线期间每60秒查看待确认回执，退到后台不承诺定时执行。指数退避上限5分钟；401停止并提示凭据，429尊重服务端等待时间。

手机只查询自己未完成的captureId对应回执，不每分钟扫描整个知识库。按设备/月分目录控制规模，但不能假定任何月份都少于服务端单次返回上限；列举完整性与分页必须纳入试验。

WebDAV传输放在平台HTTP适配层，不能为了绕过浏览器CORS而悄悄引入公共代理。凭据保存在设备安全存储，不进入manifest、页面持久化JSON或坚果云目录。

## 5. 共享代码边界

只抽出采集表单、格式校验、Capture类型、上传状态机和可纯函数测试的工具。桌面Notes/Wiki/Dream整套UI不强制迁移为移动组件。

平台适配接口固定为：`pickImages`、`persistCapture`、`listPendingCaptures`、`readAsset`、`httpRequest`、`loadCredential/saveCredential`、`getDeviceId`。返回可序列化值；业务层不导入Electron、Node fs、Android或ArkTS运行时对象。

Android提供Capacitor适配；鸿蒙提供ArkWeb–ArkTS桥接适配。仅可信本地页面能调用桥接，外部网页在系统浏览器打开。首版系统“分享到FlowNote”作为试验加分项，不作为最低交付条件；手动打开、粘贴链接/文字、选择图片必须可用。

## 6. 试验门槛与止损

### Android：最多3个实施工作日的首轮试验预算

目标是可行性检查，不是承诺3天完成产品。用同一套采集页完成安装、中文输入、图片选择、本地离线保存、杀进程恢复、WebDAV上传、Windows入库与回执展示。

必须通过：

1. 离线创建20条混合采集，杀进程重启后全部存在。
2. 上传期间断网/恢复10次，无丢失、不重复入库。
3. 两个模拟设备同毫秒各生成10条，无名称冲突。
4. Windows在ready先到、附件后到时等待，附件齐后只入库一次。
5. 手机错误凭据/额度限制能停止重试并显示可处理状态。
6. 目录超过750项的模拟服务下不会静默漏项；实际坚果云做小规模真连接验证，不为了测试大量上传真实材料。

若需要自建服务器才能完成基本上传，或可靠离线保存无法成立，停止该路线，保留Windows与既有坚果云入口。

### 鸿蒙：Android协议稳定后，最多3个实施工作日的首轮试验预算

必须在目标原生鸿蒙真机验证安装与签名、ArkWeb加载本地React页面、中文输入、图片选择、离线持久化、WebDAV和回执。模拟器跑通不能替代真机通过。

若核心插件缺失需要长期原生开发，或必须重写主要UI才能达到采集目标，结束试验并提交问题清单，不改用Flutter/uni-app重写Windows来“顺便解决”。无目标真机时报告“未验证”，不宣布鸿蒙已支持。

最终可接受交付有三种：仅Windows；Windows＋Android采集；Windows＋Android＋鸿蒙采集。三种均符合用户约束，采用已通过验收的最小组合。

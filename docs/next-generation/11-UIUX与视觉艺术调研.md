# FlowNote 下一代 UI/UX 与视觉艺术调研

2026-09-23，研究稿。用户选定主方向：**温润的编辑室与纸感**。本文借鉴优秀产品的层级、排版和交互处理，不对标 Get 笔记的视觉，不修改应用代码。设计对象是 R3 的“记录→找证据→推进目标→复盘”旅程；功能与导航名称仍可随 G2 原型验证调整。

## 2. 当前界面的静态审计

审查了 `src/renderer/components/Sidebar.tsx`、`NoteCard.tsx`、`NoteDetailDialog.tsx`、`QuickInput.tsx`、`src/renderer/pages/NotesPage.tsx` 及 `src/renderer/styles`；未运行应用进行实机视觉测试，因此以下是由代码推断的风险，非用户主观评分。

- 侧栏固定240px、路由用数字索引，且菜单英文/中文混用、用 emoji 作为主要图标；新目标/资料/成果加入后会扩成更长的平铺菜单。R2 的 PageId 改造依然有价值，信息架构却应按真实主任务而非功能数量重排。
- 全局文本基准13px，快捷输入也是13px；笔记卡片中分类、日期、AI状态、加附件、删除都挤在头部。长时间阅读与中文扫描可能吃力。Wiki正文14px/1.8较舒适，说明可复用其阅读节奏而不是把整个软件放大。
- `.note-card` 有边框、阴影、悬浮位移和入场动画；侧栏激活块有渐变、阴影、弹性移动；全局还给所有元素统一颜色过渡。各局部都想吸引注意，会和新来源证据、目标状态争夺焦点。
- 详情是模态弹窗并直接展示原文，网格卡片和单列卡片的打开方式不一致。未来“看来源→对比笔记→更新目标”需要保留上下文的详情面板或分栏，不能让每次跳转都丢掉原列表位置。
- 三套主题与自定义字体已有基础，值得保留；但主题色变量与具体控件样式仍夹杂固定颜色和局部渐变，后续需统一为语义 token。QuickInput 的语音按钮属于既有功能，UI调整不意味着新增录音/转写。

## 3. 推荐艺术方向：宁静的知识编辑室

画面应让人想到摆好材料的工作桌，而不是数字仓库：温暖但不泛黄，清楚但不冰冷。**纸感由接近纸张的底色、柔和的层次、恰当的行距和少量分隔产生**，不在正文背后叠高频纹理、噪点或大面积渐变。卡片只在“独立对象”需要被拿起或比较时出现；普通列表、来源和复盘记录优先用排版对齐与留白分组。

初步浅色 token（仅供原型，不代表已改 CSS）：背景 `#F7F5F0`，正文墨色 `#1F2928`，次级文字 `#56615D`，重点深青 `#126F68`，卡片接近 `#FFFEFC`；危险操作另用有文字标签的红色。深色沿用现有用户偏好并做对应校准：底色 `#171B1B`，正文 `#E6ECE7`，次级 `#A8B7B1`，强调约 `#70C4B4`。上述浅色正文/背景、次级/背景、强调/背景对比分别约13.7:1、5.9:1、5.5:1；白字/深青约6:1。实际 UI 仍需逐一验收控件状态和焦点。[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

字体优先系统可用的中文与西文字体，不为了外观捆绑庞大字体文件。建议正文阅读从15–16px、约1.7行高做样稿，侧栏/控件从13–14px起，不用11px承载必要状态；宽屏阅读栏限制在约34–42个汉字宽，长文可调字号/行宽/行距。日期、元信息轻于正文但保持可辨。标题层级主要靠字重、字号和间距，不给六级标题分配六个醒目色相。正文选中的来源、冲突和用户确认的结论，优先用明确标签及边界表达，不能只靠颜色。

两个可比较的备选：一是更冷静的专业工具（中性灰＋蓝，信息密度高）；二是精简的深色沉浸模式（沿用当前 dark 但去渐变/阴影）。推荐浅色编辑室作为新默认方向，深色同等完整支持；最终以同一组任务在三套主题下实际测试决定，不凭审美形容词定稿。

## 4. 信息架构：围绕“现在在做什么”而非模块数量

原R2将“笔记、知识库、搜索与问答、Wiki、Dream、成果”固定为六个主入口；如今目标闭环优先，强行维持六项会使最重要的工作藏起来。原型建议两个入口级别：**常用：记录/笔记、我的目标、查找**；**工具与历史：知识库、Wiki/Dream、成果、设置/任务**。具体名称、排列和是否合并 Dream，需在 G2 样稿中用真实路径试，不提前写死到路由。

状态保持规则比菜单样式更重要：从搜索结果打开一篇文章、跳到其引用笔记、返回时仍在原查询/滚动处；从目标复盘打开证据后返回，保留当前草稿；切主题/深色模式不重置选中资料；“返回”能预测去处。搜索与 AI 问答在同一语境中但动作分明：输入即本地关键词查找，显式点击才发送给 DeepSeek，不能把搜索框画得像会自动回答的万能入口。

宽屏可试“左导航｜中间列表/目标脉络｜右侧内容/来源”三层，但阅读/编辑只保留当前必需层；中窗口折叠导航，窄窗口转为单内容层和可返回的面板。800×500、1366×768、1920×1080和200%缩放都要看；侧栏不应在窄窗口仍固定240px吞掉正文。Windows系统标题栏、拖动区、焦点顺序须在 Electron 中实测。

## 5. 四条关键使用路径的界面草案

### 快速记录

启动后光标可快速到输入处，写一句话即可保存；附件/链接是同一采集区的清楚入口。保存时立即呈现“已保存”，OCR/分类的后台状态低调附着在条目上；失败可重试且内容一直可读。输入框不要求先决定分类、目标或文章类型。保存后可选“关联某目标”，不把这一步设为阻塞。

### 目标回看

目标详情首先显示用户写的目标、上次确认的决定和最近一次回看时间。中间是按时间排序的实际记录；右侧或下方才是“可能相关”候选，且注明为什么出现。复盘从一个问题开始，例如“上次决定之后发生了什么？”系统无证据时显示“尚无记录”；用户可以补一句自己的经历。AI建议默认处于待采纳区，不能与用户确认的下一步使用同一视觉标签。

### 阅读与对照

阅读区呈现网页快照/笔记原文，局部选择后可问“这段与我的目标有何关系”。对照结果有两端来源和可点的段落，显示网页/我的笔记/系统推断的角色。链接只抓到标题时界面为“仅链接”，不预留像摘要成功的卡片。证据抽屉可打开而不遮盖正在读的主段落。

### 写作与成果

写作时左侧素材篮和正文可以同屏，素材可收起；生成提纲、确认、草稿、版本是逐步动作，不把四个按钮同权放在每一屏。来源标记始终能预览。AI改写返回作为候选 diff，用户可以接受/拒绝；手写文本是主角。空白成果页先问“这次想表达什么”，再提供精选素材，不自动塞入一篇通用长文。

## 6. 可访问性与动效的硬验收

正文与普通控件文字至少按 WCAG 4.5:1 对比度校验，大字与必要图形至少按相应标准；不能只测色板。[W3C 对比度标准](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 小图标按钮至少满足 WCAG 2.2 的24×24 CSS像素目标或足够间距，常用操作优先做32–40px；键盘 Tab 顺序、可见焦点、Escape关闭、Ctrl+S保存、中文输入法组合、屏幕缩放都要测。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

保留反馈性动画，例如面板展开和保存状态变化，避免全局200ms过渡、每条卡片入场跳动、过冲侧栏滑块；支持 `prefers-reduced-motion`。AI运行态用明确文字“正在解读/等待网络/需要确认”，不只转圈。错误信息指出资料是否已保存、哪个步骤失败、用户可做什么。三种主题下必须能区分“用户记录”“外部资料”“AI候选”“已确认决定”。

## 7. 下一份可交给 GPT-6-Sol 的设计资料应是什么

在 G2 阶段先产出同一套公开/合成内容的4个低保真流程图和3个高保真关键屏：记录页、目标复盘页、带证据的阅读/对照页；成果页可稍后。每屏至少有空、处理中、失败、无证据、长文与窄窗口状态；同时做浅/深主题。对照旧界面完成四条任务，记录点击/返回次数、是否误解来源状态、是否丢草稿、视觉疲劳和用户偏好。设计 token 与组件清单经验证后再更新05/06，交给 GPT-6-Sol high/xhigh 分包实施。

本文件是 UI/UX 调研与建议，不把未验证的目标模块或网页解读伪装成现成界面；目前还没有运行中的 FlowNote 截屏实测，也没有给 Get 做视觉对标。

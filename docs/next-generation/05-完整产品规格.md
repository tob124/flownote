# FlowNote 3.0：对标 Get 的完整产品规格

修订 R2，2026-09-22。用户已确认“综合升级”，实施模型改为 GPT-5.6-Sol。本文件把原方案中若干“后续增强”提升为本次 Windows 正式版的必交付能力；基础数据和第三方接口继续遵循 02。

## 0. 本次究竟升级什么

上一版适合作为 Alpha：接入图片/网页、能搜索、能引用回答。本次完整目标是让资料经过收集后，能够围绕一个长期问题组织、对话、产生启发，最后形成可修改和回看的成果。Alpha 仍分阶段交付，但不再被称为整个下一代升级完成。

### 0.1 已确认边界：不得被执行模型扩展

| 用户约束 | 施工含义 |
|---|---|
| 个人自用 | 不做多人权限、收费、账号后台和公共知识库 |
| Windows为主 | 保留Electron，Android/鸿蒙仅可选轻量采集，不承担桌面全部能力 |
| 坚果云继续重要 | 原始资料和成果仍是可同步文件；不引入自建云来替代坚果云 |
| 不设计语音识别 | 不新增ASR、录音转写、声纹、手机内录、直播转写或录音硬件 |
| DeepSeek＋PaddleOCR，成本不要高 | 分类/问答/理解使用已有供应商；无必要不增加付费模型、后台无限调用或全库重处理 |
| 保留并增强Wiki/Dream | 月度分类Wiki和自动Dream继续存在，主题知识库不能替代、打散或删除旧结构 |
| 对标Get为重点 | 主线是采集、组织、调用和成果；旧TODO只纳入支撑主线的部分 |
| 本会话仅调研和文档 | 不启动代码施工、不做真实库迁移、不调用付费API |

产品对标与工程实现分开：Get 的能力存在不意味着其内部算法已知。本方案中的本地检索、限额与单写入者都是 FlowNote 的选择。

### 0.2 对标映射与新增幅度

| Get方向 | FlowNote 3.0正式交付 | 与上一版的实质差异 |
|---|---|---|
| 图片/链接/文件成为知识资料 | 图片、公开链接、TXT/MD、PDF、DOCX统一提取、来源查看 | 文档解析进入正式范围，而非遥远待办 |
| 多个主题知识库 | 一条笔记进入多个主题；主题内资料、问答、洞察、成果 | 从一个简单集合字段变成完整主题工作区 |
| 自然语言调用记忆 | 全局/主题问答、有限轮追问、证据抽屉、会话保留 | 从单次问答扩展为可持续的知识对话 |
| 发芽、点评、拷问 | 关联、反思、点评三种明确上下文的手动动作 | 独立结果卡、双端引用、采纳/忽略，不只多写几个提示词 |
| 记忆累积与阶段回顾 | Dream有依据、覆盖说明、待追问事项、结果进入主题/成果 | 保留旧自动流程，新增真正可继续使用的输出 |

| 日常记录与管理 | 收藏、组合筛选、明确选中项批量操作、Markdown编辑/预览、可恢复删除 | 让新增资料规模能够被日常管理；不做Notion式块编辑器 |

排除项保持：语音全链、直播/博主自动订阅、社交媒体登录爬虫、评论区全量备份、硬件、团队、人格画像、知识图谱、PPT自动生成。向量检索不作为本轮前提；若同义召回不达标，作为独立提案，不由Sol擅自更换存储与模型体系。

## 1. 最终用户旅程与导航

### 1.1 必须跑通的完整场景

用户保存一段个人思考、一张截图、一篇公开文章和一份PDF → 找到相关旧笔记 → 加入“长期学习方法”主题 → 在该主题内提问并追问 → 对其中两条笔记生成关联，或对一个观点生成反思 → 把选中的材料及洞察用于一篇复盘 → 修改成第二版 → 导出带来源清单的Markdown。每一步均可回到原文；关闭应用、断网或模型失败不影响已有内容。

### 1.2 导航结构

主导航顺序固定：笔记、知识库、搜索与问答、Wiki、Dream、成果。统计、任务与通知、设置放在辅助区。任务面板与通知可复用现有通知页的分区，不另造三个状态中心。首页仍为笔记；没配置目录才进入设置。

把现有0–5的页面数字索引迁移为共享 `PageId` 字符串联合；旧值对应 notes/wikis/dream/stats/settings/notifications。新导航只有一份配置，Sidebar和App都读取它，不能分别维护序号。内部来源跳转使用实体ID和SourceRef，不依赖组件数组位置。

知识库详情四个页签：资料、问答、洞察、成果；顶部显示名称、说明、有效资料数和“添加资料”。范围切换必须可见，不因打开一个主题悄悄改变全局搜索的默认范围。

## 2. 笔记与资料管理规格

### 2.1 编辑与显示

快速输入保留轻量textarea及Alt+Enter；点击展开打开专业Markdown编辑区。详情提供阅读/编辑/分栏预览。采用CodeMirror 6的React薄包装，复用现有react-markdown/remark-gfm预览，不把整个编辑器应用移植进工程。[CodeMirror官方文档](https://codemirror.net/docs/guide/)

工具栏首轮只提供粗体、斜体、标题、列表、引用、链接、代码。下划线不是本项目GFM基础语法，首轮不以开启任意HTML来实现；高亮扩展也不作为交付前提。正文以Markdown字符串存储，不能在打开、预览时自动重排或改写原文。

编辑草稿每1秒空闲后保存本机草稿区，不同步、不触发分类/Wiki。Ctrl+S或保存按钮提交正式版本。关闭有改动的编辑器提供保存、保留草稿退出、放弃；恢复草稿前比较底稿hash，冲突显示两份文本，不自动覆盖。中文输入法组合期间不得误保存、关闭或打断候选词。

正文修改使相关AI字段标记过期，默认排一次新分类，但已被用户确认的标题/分类/标签保留；新分类只建议更新这些锁定字段。原Wiki标记来源有变更，不在每次按键后重写。附件增删只触发对应来源与索引失效，不无条件重跑所有AI。

### 2.2 浏览器能力

保留单列/网格。筛选项为关键词、category、标签、收藏、个人/外部资料、来源类型、处理状态、日期。不同筛选项之间AND，选中多个标签按OR；日期按本机自然日，闭区间。默认新到旧排序，可选旧到新，不加入按首字母排序。

多选只作用于用户实际勾选的ID；不提供跨整个库的“全选”，不随翻页或搜索把隐藏条目默默加入操作。切换筛选时保留选择并显示“已选N条，其中M条不在当前结果”；批量确认界面必须能查看实际列表。

批量操作：收藏/取消收藏、增加/移除标签、加入/移出主题、移入回收站。禁止首轮批量移动category、批量重写正文、自动重分类全库。每次最多100条，超过让用户分批。部分失败按ID显示原因，只重试失败项，不重做已成功项。

### 2.3 回收站

删除改为软删除，持续保留直到用户手动清空，不自动永久删除。移入回收站即从搜索、主题有效成员、AI候选中排除，取消尚未执行的任务，运行中结果不得回写。恢复保留原ID和主题成员关系；原引用可恢复有效，但已生成答案仍保留其产生时的版本信息。

底层Note新增 `deleted_at_ms?`；旧 `notes.delete` 兼容入口映射到软删除。永久删除仅在回收站页显式确认，先写删除标记/回执再移除文件，保留capture_id去重回执。关联附件在本轮不做自动垃圾回收，避免误删共享资源；设置中展示“可能未引用附件”供后续独立处理。

## 3. 主题知识库规格

### 3.1 语义

界面叫“知识库”，内部沿用 `Collection`，避免与整个sync_dir的Library混淆。category是单一主分类并决定旧Wiki归属；Collection是跨category的多对多引用；标签是描述与筛选。这三者不能合并成同一个字段。

成员只接受Note ID。一个有多个图片/文件来源的Note加入主题后，其有效Source一起进入该主题。资料页可以展开到Source；索引构造时去重，不因Note和Source同时出现而计算两份材料。主题不复制正文，不自动改category，也不自动使外部资料参与全局Wiki/Dream。

### 3.2 CRUD与推荐

创建时名称必填1–60字符、说明可选最多1000字符；允许重名，以UUID区分。名称不是文件路径。编辑名称/说明，成员增删均记录revision。删除主题只删容器，笔记和成果保留；成果标注原主题已删除，会话变只读并允许复制问题到全局新会话。

“添加资料”打开带搜索与多选的选择器。“推荐相关资料”先用主题名称/说明在本地查询，展示最多20个候选和命中片段，默认不调用AI；用户可手动用DeepSeek优化一次查询词。必须逐批确认添加，不自动搬运全库。

资料为空：展示创建/添加入口，问答和创作按钮解释需要资料。资料处理中：显示已可用与处理中数量；用户可以基于已可用部分执行，但答案明确覆盖范围。失效或回收站成员保留关系并在管理界面可见，默认不作为可用材料。

## 4. 知识问答与会话规格

02定义的单轮引用问答作为Alpha。正式版在同一服务上增加会话，不换检索底层或增加无限Agent循环。

- 会话创建时固定范围：全局或一个Collection。改变范围创建新会话，不让旧对话悄悄跨库。
- 每次提问重新校验主题有效成员。主题资料有变化时显示提示，本轮使用当前资料快照，并保存此次scope revision与输入hash。
- 最多发送最近4个已完成问答回合的文本，历史部分合计最多4000字符；超过按完整回合从最旧移除，UI提示早期对话不在本次上下文。更早消息仍可浏览。
- 有追问上下文时，最多一次模型调用把问题改写为独立查询；剩余一次用于带引用回答。没用改写时可用额外一次格式修复。每轮最多2次，不叠加多代理。
- 历史回答只能帮助理解“它/上次那个观点”等指代，不能作为证据；证据仍来自本轮最多8片段/8000字符的SourceRef集合。
- 用户问题上限2000字符，回答输出上限1600 tokens。普通本地搜索仍0次调用。
- 提交问题后马上持久化用户回合，再启动任务；消息状态queued/running/completed/failed/cancelled。失败重试复用该回合ID，不能多出一条相同用户消息。完成回合后重试视为“重新生成”，创建候选版本，不静默覆盖旧回答。
- 每会话同时只允许1个生成任务；切页可后台执行，取消立即停止本机后续阶段。返回时再次核对库ID、会话状态和来源可用性。
- 会话历史默认保存到同步目录；删除会话后取消任务、不删原资料。问答“保存为成果”只引用选中已完成回合，不能让整段聊天自动进入个人笔记。

来源证据抽屉显示：实际引用的原文片段、标题、日期、类型、当前有效/已变更/已删除状态。引用只能引用源资料；推测单独标记。“有引用”不等于“已验证推理正确”，仍使用事实题和人工复核验收。

## 5. 关联、反思、点评

这三类是 Get 发芽/拷问/点评在 FlowNote 中的具体落地，UI统一称“洞察”，动作名称保持清晰。

| 动作 | 输入范围 | 输出 | 调用上限 |
|---|---|---|---|
| 关联 | 当前笔记/来源＋本地召回最多6条其他材料；主题内触发则限制该主题 | 最多3条有理由的关联，每条引用两端材料 | 通常1次，修复最多另1次 |
| 反思 | 当前笔记或当前Wiki，可附用户问题；默认不带其他历史 | 最多3个可讨论的问题，指出原句、理由和可能反例 | 同上 |
| 点评 | 当前对象；评价表达清晰度、证据和可行动性 | 优点、待澄清处、建议各不超过3条；避免空泛赞美 | 同上 |

手动触发，输入材料总计最多8000字符、输出上限1200 tokens。超出先让用户选段或章节，不能静默只读开头却表示已读全文。关联无候选、没有足够证据或未发现有意义关系时允许空结果，不能强行凑3条。

Insight保存输入SourceRef和结果类型。结果操作为收藏、忽略、加入成果素材；“采纳为笔记”创建显式标注AI辅助的新Note，其origin为derived、include_in_wiki默认false，保留derived_from引用。默认索引和自动Dream排除derived，只有用户显式允许派生内容时才参与，防止自己的输出反复被当作新证据。

忽略只影响该结果的展示，不删除资料。相同输入hash、类型、模型、提示词版本复用已有结果；“重新生成”是显式付费动作，生成新记录并显示次数，不自动循环刷新。

## 6. Dream增强：从报告到可使用的洞察

保留当前自动触发与短报告。首页仍提供时间范围、阈值、开始整理，不做每天推送新通知的强制习惯产品。

每次Dream保存：本次符合条件的数量、实际使用的ID/版本、未覆盖数量、采样方法、短报告、结构化主题/矛盾/关联/反思条目及引用。结构化条目与短报告在同一次请求返回，不为每个条目二次调用模型。默认最多100条且材料总计上限12000字符，以真实周分组轮流加入完整短笔记；长笔记使用明确标注的节选。源引用保留实际使用片段，不能把节选当全文已覆盖。

Coverage以笔记输入hash＋已分析segment范围记录；完整笔记/全部片段才算fully_covered。自动计数以新增未处理版本为触发依据；一次自动Dream对每个版本最多自动尝试一轮取样，剩余部分标partial并提供手动深入，不因partial永远满足阈值而重复自动计费。失败不登记已处理；成功报告展示partial，不宣称全量理解。

首次升级把旧的已完成笔记登记为baseline，不触发历史库付费重跑。用户可手动选择历史时间范围分析。成功游标仅用于显示，处理覆盖清单才是防漏/去重依据。

用户可以把一个Dream条目加入主题或成果，但这只保存Insight引用，不自动把它当成原始资料；主题问答默认仍检索原笔记。可浏览旧Markdown报告，旧报告没有引用时标注历史格式，不补造证据。

## 7. 成果工作台

### 7.1 成果类型与流程

支持复盘、主题综述、观点短文三类模板；周报作为复盘的“最近7天”快捷方式。允许用户改标题和写作要求，不提供PPT/公众号发布/长图导出/AI专家团队。

固定流程：选择范围或明确素材 → 检查素材篮 → 生成提纲 → 用户编辑并确认提纲 → 生成草稿 → 用户编辑/选择局部改写 → 保存版本 → 导出Markdown。

素材篮最多12项。范围检索只提出候选，用户看到将使用哪些材料后才调用生成。每次生成取材料节选总计最多12000字符；超出提示缩小素材或选片段，不能整库发送。Insight作为灵感可以选择加入，但必须同时保留其原始证据引用并标注派生性质。

提纲与草稿是两个独立动作，每个动作最多1次正常调用＋1次失败格式修复。输出上限：提纲800 tokens、草稿3000 tokens、局部改写1200 tokens。无素材时可以手写成果，但AI生成必须有材料或用户主动输入的写作内容，不自动联网找材料。

### 7.2 编辑、版本与导出

成果编辑复用Markdown编辑器。草稿自动保存于本机，每次用户“保存版本”生成不可变版本，记录parentVersionId、作者类型user/ai、材料SourceRef、模板、提示词/模型及时间。版本恢复创建新版本，原版本不删除。版本标题V1/V2只按持久化序号显示，底层用UUID。

局部改写只替换用户选区，先显示前后对照；用户接受才应用编辑草稿。请求期间用户已修改同一段，返回候选不能直接应用，必须重新核对底稿hash。保留草稿与版本的区别，不能每个按键创建同步版本文件。

导出 `.md` 包含正文和可读来源附录：网页写URL/采集日期；个人笔记写标题、日期、ID和引用片段；文件写原文件名/页码。不要让导出物只剩其他电脑无法识别的内部deep link。原图与附件首轮不打包，附录注明仍在原库。

“保存为笔记”创建origin=derived的笔记并关联成果版本，不自动排分类/Wiki/Dream；用户可显式纳入，UI提示其为AI辅助/成果回存。删除成果只删除成果容器及其版本，不删除素材。没有“自动发布到平台”的入口。

## 8. 新增模型、持久化与服务契约

### 8.1 共同约定

新实体采用UUID，ISO字符串不用于排序游标，时间用UTC毫秒；展示按本机时区。所有实体带schema_version、created_at_ms、updated_at_ms，所有可修改实体带revision整数。更新必须携带expectedRevision；不匹配返回CONFLICT，不以最近一次写入静默覆盖。

共享 `Result<T>` 为 `{ok:true,data:T}` 或 `{ok:false,error:{code,message,retryable,details?}}`。错误码至少包括VALIDATION、NOT_FOUND、CONFLICT、CANCELLED、SOURCE_CHANGED、SOURCE_UNAVAILABLE、AUTH、RATE_LIMIT、QUOTA、NETWORK、IO、UNSUPPORTED、INTERNAL。新增IPC返回Result，旧接口由兼容包装转换，不一次性破坏现有所有调用者。

### 8.2 字段与存储

| 实体 | 业务字段 | 保存位置 |
|---|---|---|
| Note新增 | favorite默认false；deleted_at_ms?；revision默认0；manual_fields为用户已确认AI字段名集合；origin加入derived；derived_from? | notes沿用原文件 |
| Collection | name, description, member_note_ids, revision | collections/<id>.json |
| Conversation | title, scope={kind:global或collection,id?}, revision, read_only_reason? | conversations/<id>/meta.json |
| Turn | request_id, question, answer?, citations, job_id?, state, scope_revision?, input_hashes, context_turn_ids, usage? | conversations/<id>/turns/<turnId>.json |
| Insight | kind=link/reflect/comment/dream, target_ref, evidence_refs, body_markdown, items, favorite, dismissed, generation_key | insights/<id>.json |
| Artifact | title, template=review/synthesis/opinion, collection_id?, current_version_id?, revision | artifacts/<id>/meta.json |
| ArtifactVersion | parent_version_id?, sequence, author_kind, body_markdown, outline, source_refs, model?, prompt_version?, usage? | artifacts/<id>/versions/<id>.json |
| Draft | entity_kind, entity_id, base_revision, base_content_hash, text, selection?, saved_at_ms | 本机库目录/drafts/ |

Insight.items分别为关联对、反思条目、点评条目或Dream条目，字段只含文本与SourceRef；不接受模型返回的任意文件路径、工具名或数据库操作。

### 8.3 服务接口

| 命名空间 | 操作与必要输入 | 返回/行为 |
|---|---|---|
| notes | patch(id,expectedRevision,patch) | 最新Note；patch只允许用户字段，不能手改任务状态 |
| notes | bulk({ids,operation,payload?}) | 每ID成功或错误；单批≤100，校验后按ID稳定顺序执行 |
| notes | trash/restore(id,expectedRevision) | 最新Note；旧delete映射trash |
| drafts | get/put/discard(entityKey,baseRevision,text) | 本机草稿；不排AI任务 |
| collections | list/get/create/patch/remove；setMembers(id,expectedRevision,memberIds) | revision增长；成员以Note ID去重 |
| conversations | create(scope)/list/get/remove；send(id,requestId,question) | send返回turnId＋jobId；相同requestId返回同一回合 |
| insights | generate(kind,target,scope?)/list/updateState(id,favorite,dismissed) | generate返回jobId；按generation_key复用 |
| artifacts | create/get/list/patch/remove | 元数据；旧版本不可原地修改 |
| artifacts | outline(id,requestId,sourceRefs,instruction)/generate(id,requestId,outline,sourceRefs) | 返回jobId，完成后产生候选草稿，不静默覆盖已保存版本 |
| artifacts | saveVersion(id,expectedRevision,draft)/restoreVersion(id,expectedRevision,versionId)/export(id,versionId) | 新版本或系统保存对话框结果 |

这些接口是规格，不要求照表生成一个巨大万能服务。按实体分模块，IPC→参数验证→服务→存储/任务→事件；不能由React直接串联“保存版本+修改当前指针”等多步事务。

### 8.4 跨文件提交与删除

成果版本先写不可变内容，再以expectedRevision更新meta当前版本指针；提交日志记录目标hash和新指针。崩溃恢复时可补齐指针，不调用模型。结果回传后若meta已变化，保留候选，用户选择另存版本。

Note软删除后，主题保留成员ID但排除其有效资料；Conversation/Insight/Artifact保留历史引用并标失效，不自动删除生成历史。恢复Note后重新索引。永久删除操作若失败须保留可恢复删除日志，不半成功地对UI报告完成。

## 9. 成本与默认自动化

本节“最多2次”指单动作实际发出的模型HTTP请求总数，包含问题改写、回答、格式修复和网络重试，共享持久化预算；不是每个子步骤各有2次。网络重试耗尽预算时停止生成并展示可恢复失败，不额外增加调用。T03通用最多3次尝试是外层上限，遇到单动作2次上限取较小值。预算在发出请求前持久化扣减；远端是否已接受不确定时停止自动重发。人工重新生成需显式发起新动作并显示已有尝试次数。

编写软件的模型改为GPT-5.6-Sol，不意味着FlowNote运行时改用GPT，也不意味着每条笔记都增加更多自动模型步骤。运行时继续DeepSeek/PaddleOCR。

| 能力 | 自动还是手动 | 费用边界 |
|---|---|---|
| 分类、短摘要、Wiki | 延续自动，任务去重/小批合并 | 02的并发、缓存和长文保护 |
| 新图片OCR | 新采集默认，可关闭 | 成功缓存；同任务续查；额度错误不自动付费回退 |
| Dream | 保留阈值自动与手动 | 每新增版本一轮自动取样；结果覆盖可见 |
| 知识库推荐资料 | 默认本地 | 0调用；优化关键词手动1次 |
| 问答/追问 | 用户提交时 | 每轮最多2次 |
| 关联/反思/点评 | 手动 | 通常1次，最多2次 |
| 成果提纲/草稿/改写 | 分动作手动 | 每动作通常1次，最多2次 |
| 手工编辑/收藏/筛选/版本/导出 | 本地 | 0调用 |

新增动作都显示“将使用N份资料”和调用中/成功/失败状态；任务页按功能统计token、页数和请求次数。只统计供应商实际usage，不能把估算当账单。设置可配置当日自动DeepSeek生成请求上限，默认100，包含失败的实际请求；按本机自然日计数并持久化，达到后暂停对应自动队列。OCR提交/轮询单独统计且遵循供应商额度，不计入此100次；手动操作仍由用户触发并提示已有用量。额度不是跨设备共享账单，单写入者和本机持久化计数是首轮边界。

## 10. 交付与验收层级

- Alpha：T00–T11，采集/检索/引用/可靠性可用，允许用户提前体验；这不代表3.0完成。
- Beta：T12–T21，主题知识库、会话、洞察、Dream增强、成果工作台和管理编辑全部联通。
- 正式：T22通过完整流程与回归，产品版本才升级3.0.0。
- 可选移动：T23/T24；不阻塞Windows正式版，也不绕过真机验证。

窗口尺寸维持现有最小800×500；窄窗口将证据抽屉/素材篮改为覆盖层，不能挤到正文不可操作。三套主题、自定义字体、输入法、键盘保存、关闭恢复均纳入回归。

性能/AI质量门槛仍以测试样例与实测记录为准；API不可用时标注未验证，不能伪造通过。没有扩大语音、服务端、社交采集或硬件边界。

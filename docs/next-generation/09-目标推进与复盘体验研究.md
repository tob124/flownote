# 目标推进与复盘：FlowNote 下一代的优先验证闭环

R3 调研稿，2026-09-23。用户已选“持续推进目标与复盘”为“life leader”愿景中最想优先解决的真实问题。本文定义待验证的行为与失败边界，不在本轮施工，也不预设新首页或视觉样式。目标是让用户自己的记录更容易转成判断与行动，系统提供证据和选项，用户保留决定权。

## 1. 为什么旧计划还不够

R2 已有主题知识库、Dream、洞察和成果，但缺少一条明确的线：**我正在做什么 → 哪些资料与之相关 → 我决定了什么 → 我是否真的推进 → 结果教会了我什么**。主题只是资料容器；Dream 是定期报告；成果是文档。它们都可能很好看，却不能回答“我上个月决定练习什么，现在为什么还停在这里”。

因此首要产品问题不是增加待办页，而是让一个**用户明确提出的长期目标**拥有可追溯的状态。FlowNote 既不根据零散笔记暗推人生目标，也不自动把模型建议写成用户计划。

## 2. 一个必须跑通的实际旅程

示例使用公开/合成资料，不能宣称代表用户真实生活：

1. 用户写下“未来三个月建立稳定的英文阅读习惯”，自己定义为何重要、预计如何知道有进展、何时想回看。可只写一句话，指标可空。
2. 用户捕捉阅读笔记或网页时，可选择关联此目标；不关联也能用。系统从已关联资料、用户选定的主题和低风险本地召回中提出少量候选，说明关联原因，用户确认后才加入目标证据。
3. 用户做出一项决定：“每周读两次，每次20分钟”，可记下当时的依据、顾虑和复查日期；它是用户决定，不是模型推断。
4. 下次手动打开“回看”时，系统首先呈现上次决定、已有进展/未找到进展的区别、相关记录和可能阻碍；若资料不足就问一个澄清问题。用户可以标记已完成、暂缓、改变目标、指出建议无关，或选下一步。
5. 数周后系统对照当时的预期与实际，展示“当时以为/后来发生/现在的判断”；用户确认的经验可保留，供未来类似决策调用。

任何一步离线时，已有目标、笔记、决定和手动复盘仍可编辑；AI 部分不可用只意味着暂时没有候选解读。

## 3. 最小对象，不造庞大任务管理软件

| 对象 | 必要字段及语义 | 明确禁止的混淆 |
|---|---|---|
| Goal | 用户写的名称、动机可选、状态 active/paused/completed、创建/回看时间、可选成功信号 | 模型从笔记推断的愿望不得自动建 Goal |
| Commitment | 用户确认的下一步、到期/复查时间可选、状态、所依据的 Goal | “AI 建议”不能直接成为未完成任务 |
| Decision | 用户写的选项/选择、理由、疑虑、当时 SourceRef、复查日期可选 | 回顾时不能把后来知识改写成当时已知 |
| CheckIn | 手动复盘的时间、用户自述、完成/受阻/调整、下一步可选 | “没有记录”不等于“没有行动” |
| Candidate | 系统建议关联的旧资料、冲突、问题或下一步，带生成依据和用户反馈 | 未采纳候选不能写成稳定的用户偏好 |

沿用 R2 的 Note/SourceRef/Collection/Insight/Artifact 作原材料。Goal 与主题知识库可以关联，但不是同一概念：主题组织资料，Goal 记录用户想推进的变化。单个目标可以涉及多个主题。最初只需这几个对象与引用，不要求知识图谱、日程集成、多人协作、积分、打卡连续天数或习惯追踪算法。

所有用户可编辑对象采用 revision 冲突保护；AI 候选带输入版本与过期提示。同步仍是坚果云上的可读文件；自动请求遵守05的成本总额。这里是候选信息模型，文件名和 IPC 待 G4 验证后再定。

## 4. 复盘真正有用的输出

复盘起点应是用户的问题：“上次决定后有什么变化？”“哪里受阻？”“现在还值得继续吗？”系统优先取：目标文本、用户确认的 Commitment/Decision、上次 CheckIn、新增且用户明确关联的资料。最后才是本地召回的未确认相关候选；不能把全库随机相似笔记混成对目标的事实。

一次有效复盘给出的内容顺序：

- **已知进展：** 仅列有记录支持的变化，并显示出处；无记录明确写“暂无记录”，不宣布用户失败。
- **待确认变化：** 展示可能相关但未确认的材料，询问用户是否要纳入。
- **阻碍或变化：** 对照先前决定与后来记录，明确是事实、用户说法还是模型推断；不要求每次都找出问题。
- **一个下一步候选：** 可以是采取行动、缩小目标、先补证据或暂停；用户可以拒绝。
- **回看时点：** 用户设定或手动发起，避免软件自发催促。

“复盘”不等于固定格式周报。用户可只写一句“本周没有推进，因为工作太忙”，系统保存事实，不强行输出长篇积极话术。想要正式成果时，才把已确认的决策轨迹导入 R2 成果工作台。

## 5. 如何让主动性有帮助而不烦人

第一步只做**按需回看**：在目标详情或用户打开 Dream 时出现可用入口，不弹窗、不系统通知、不自动付费分析。若后续验证有价值，才试验“恰好相关的旧笔记”候选：必须说明触发原因和来源，可一键忽略、关闭某目标的建议、改频率。没有高质量候选就显示空态。

该顺序来自我们对产品成本和干扰的判断；[主动助手研究](https://arxiv.org/abs/2005.01322)也指出过度打断及隐私泄露是主动交互的风险，但该研究是语音助手场景，不能直接当作 FlowNote 的效果证据。

在人生目标与重要决定上，解释和引用也不能替代用户独立判断。[人机决策研究](https://arxiv.org/abs/2301.07255)发现某些解释形式可能增加错误依赖。FlowNote 应将“依据”“假设”“还缺的信息”并列，并让用户能改写建议；不以模型拟人化语气声称了解用户真正想要什么。

## 6. 对 R2 功能的具体取舍

| 既有模块 | 对目标闭环的作用 | R3 调整建议 |
|---|---|---|
| 快速输入、OCR、网页快照 | 留下当时材料 | 继续做可靠采集；捕捉时“关联目标”应可选、低摩擦 |
| 分类/Wiki | 主题性回看 | 保留原流程；仅作为候选材料，不能替代用户确认的目标 |
| 全局问答 | 找过去怎么想 | 加入时间变化、更新和拒答评估后才可称长期记忆 |
| 主题知识库 | 组织某个长期议题 | 首先验证能否让目标复盘找到关键资料；四个页签不是价值本身 |
| 关联/反思/点评 | 发现盲点 | 优先做与一个具体决定/阻碍有关的反思；通用“点评”优先级降低 |
| Dream | 定期看全局变化 | 尝试以“未解决、已变化、值得回看”为输出；不默认把 100 条笔记变成行动建议 |
| 成果工作台 | 保留阶段性结论 | 使用已确认的决策和复盘记录作素材；不靠 AI 代写替代真实思考 |
| 书籍推荐 | 补认知缺口 | 等目标需求、可靠目录、读后反馈都成立；见08 |

这不是立即取消 R2 的工程设计，而是调整先后和成功定义。尤其“点评”和三种成果模板，若不能在目标闭环中展现增量价值，可以降级或留待后续。

## 7. 验证计划与退出标准

先用三个差异化的合成目标：可量化技能目标、开放式创作目标、暂时无力推进的目标。每个准备跨三次复盘的时间线、至少两条相反记录、一条已过期决定、一条看似相关但应排除的资料。人工标注哪些问题可从资料回答、哪些必须问用户。以“当前笔记搜索＋手写复盘”为对照，比较找回证据、理解变化、完成下一步决定所需的步骤和主观价值。

G4 后完成受限实现，再由用户自己选择一个真实目标，用自己的设备和数据做 G5 小范围试用数周；记录结果与错误类型，不导出私人原文到研究文档。重点问：过去的重要记录是否被带回？系统有没有误判用户行动或动机？提出的下一步是否节省思考时间？是否出现让人不愿再用的催促？用户是否能一键纠错并看到下次改善？

**继续条件：** 至少一个完整目标经历“设立→行动/受阻→回看→修订决定”，用户认为相比手动搜索与记事明显更值得继续使用；有来源的进展与“无记录”不混淆；关键用户决定不由模型自动写入。**停止/缩小条件：** 持续给空泛建议、错把旧目标当现状、把缺少记录误作未行动、频繁打扰或调用成本失控。此时退回可靠目标日志＋手动检索，保留用户数据，不追加更多 AI 提示词。

当前没有真实目标测试或可量化效果数据，所以目标闭环仍是头号验证主题；G2 可用低保真/可丢弃原型，G4 后才更新05/06并交付正式施工包，G5 在实现后检验长期效果。UI/视觉另见11。

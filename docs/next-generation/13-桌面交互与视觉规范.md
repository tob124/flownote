# FlowNote 桌面交互与视觉规范

2026-09-28。本规范是后续界面施工的共同约束，适用于 Notes、Wiki、Dream 及其局部操作。Apple HIG 提供层级、动作与导航的原则；具体尺寸和信息结构是 FlowNote 的桌面产品决定，不声称复刻原生 macOS 控件。

## 问题与取舍

原界面把保存、展开、语音、附件、润色放在同一排等权按钮；每张笔记同时出现收藏、加号、叉号、阅读、评论、荐书与追问。动作虽然存在，但用户须逐个辨认。类别彩色胶囊、完成徽章、悬浮动效和装饰文字进一步分散阅读注意力。

本轮选择安静的“个人编辑室”：稳定导航、纸页式记录、集中编辑与讨论。视觉辨识来自纸面与墨色的关系、正文排版以及细窄的选中标记，不靠卡片浮动、装饰性标签或多种图标风格。

比较后舍弃两种方案：全量工具栏（高频与低频等权）；所有动作藏进菜单（初次使用缺少入口）。最终采用主要动作直接可见、辅助动作按上下文归组的方式。

```text
侧栏             笔记                                      回收站
笔记             写下一条记录…
Wiki             [附件] [输入工具…]              Alt+Enter [保存笔记]
Dream            搜索 / 筛选
                 日期  分类                         收藏  更多
                 标题与正文
                 阅读 / 编辑                    AI 回应与讨论
记录概览
通知  设置

思考窗：原笔记标题                                    更多  关闭
        回应 | 延伸阅读 | 讨论
        当前内容 / 空状态的唯一主要动作
        与当前内容紧邻的反馈，不跨区堆放
```

## 视觉变量

- 纸面 `#F7F5F0`；页层 `#FFFEFC`；导航底 `#F0EEE8`。
- 主墨色 `#252A28`；次要文字 `#626A65`；强调色 `#126F68`。
- 危险操作沿用主题危险色；不使用绿色“已完成”徽章反复标记正常状态。
- 控件使用 Segoe UI / Microsoft YaHei 的无衬线界面字体；品牌与阅读标题可使用 Georgia / 宋体风格，尊重用户正文自定义字体。
- 字阶 12 / 13 / 15 / 20 / 26 px；正文行距 1.75–1.9。正文宽度有上限，不随大窗口无限拉长。
- 间距以 4 px 为基准：8 / 12 / 16 / 24 / 32。普通按钮高 34 px、工具图标点击区不小于 32 px、菜单项不小于 36 px。

## 动作规则

1. 每个独立任务区至多一个强调填充按钮。例如输入区是“保存笔记”，讨论区是“发送”，纠正卡片是“接纳并融入 Wiki”。这是一条 FlowNote 规则，不冒充 Apple 的逐字规定。
2. 次要按钮用于并列但非首要任务；低频选项使用“更多”菜单。文字导航不伪装成按钮，按钮文案必须解释动作。
3. 收藏可以使用通用图标；未知含义的加号、叉号不能代表添加附件与删除。统一使用线性图标，图标按钮具备名称、悬停提示和焦点样式。
4. 删除进入菜单中的独立危险组，并保留确认。不可用按钮保持可解释的上下文，不静默消失主要能力。
5. 重新生成属于已有结果的次要操作，放入结果菜单。初次生成放在空状态；“看现有结果”和“再次消耗用量生成”不能共用含混入口。
6. 导航页签只切换内容，不隐含发起 AI 请求。折叠卡片默认只有一个 AI 入口；详细窗再按回应、阅读、讨论分区。
7. 正常后台完成状态退到次要层级；失败和处理中保留可见状态与明确恢复动作。
8. 菜单支持方向键、Home/End、Escape、焦点归还和点击外部关闭；对话框支持 Escape、焦点约束；页签支持方向键；不只靠颜色表达状态。

## 依据与工具

- [Apple HIG：Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：区分操作角色，避免将破坏性操作当作主要动作。
- [Apple HIG：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：优先提供当前情境的常用命令，减轻控件对内容的干扰。
- [Apple HIG：Menus](https://developer.apple.com/design/human-interface-guidelines/menus)：组织次级动作，保持可理解的分组。
- [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)：先确定与产品相符的颜色、字体、布局和约束，再实现并用截图自审。已安装官方 skill；本轮直接阅读并使用，现已进入可用技能列表。
- [21st MCP 官方安装说明](https://github.com/21st-dev/magic-mcp/blob/main/llms-install.md)：当前版本需要独立 21st API Key；当前没有连接，不伪称调用过。无需因此阻塞本轮设计与实现。

## 验收

宽窗与最小桌面窗口均不发生控件重叠；主要任务路径可见；输入区仅保存为强调动作；笔记不出现直接删除叉号和匿名附件加号；AI 导航不会自动生成；反馈与重生成不再占满一排；键盘菜单、返回焦点、模态关闭和保存流程通过真实界面检查。

# FlowNote 下一代升级规划 · R3 调研版

更新：2026-09-23。工程基线 v2.9.0。原规划阶段仅调研与写文档；用户现已授权开始施工。T00–T02 数据可靠性底座已实现，见[施工状态](implementation-status.md)。尚未读取真实笔记或使用付费API；软件运行时模型仍是 DeepSeek/PaddleOCR。

## 当前判断

R2把 Get 笔记的采集、知识库、问答、洞察与成果流程做成25个可施工任务包，解决了“要实现哪些功能”的问题，但没有证明它们能让 FlowNote 成为更有用的第二大脑。R3 把 **持续推进用户自己设立的目标与复盘** 定为首要验证方向：准确找回过去的依据、分清观点何时改变、帮助用户形成下一步并在以后回看结果。Get 仍是功能参照，不再决定产品上限；UI/视觉已启动独立调研，选定“温润的编辑室与纸感”。

用户选定的优先方向已经记录在[09-目标推进与复盘体验研究.md](09-目标推进与复盘体验研究.md)。网页解读和书籍推荐属于高弹性能力，需先证明资料可靠且对这一闭环有帮助，见[08-网页解读与书籍推荐验证.md](08-网页解读与书籍推荐验证.md)。整体重审、能力取舍与 G0–G5 验证门槛见[07-方向重审与价值验证.md](07-方向重审与价值验证.md)。本轮计划审计见[10-计划审计与轻量检索决策.md](10-计划审计与轻量检索决策.md)，界面研究见[11-UIUX与视觉艺术调研.md](11-UIUX与视觉艺术调研.md)。

## 保持有效的用户边界

- 个人自用、Windows/Electron/React/TypeScript 优先，保留 JSON/Markdown 可读数据。
- 坚果云继续负责同步、托管和中转；不建账号后台或自有云。
- 保留并增强自动分类→Wiki→Dream，不把它们作为未经验证的唯一主界面。
- 不新增语音识别、录音转写、声纹、手机内录或音视频理解。
- 图片由 PaddleOCR 提取文字，DeepSeek 按需分析；避免全库重复付费处理。
- 移动端只可选轻量文字/图片/链接采集，Android/鸿蒙都不能阻塞 Windows。
- 本轮不做语义/向量检索，不装 embedding、向量库或仅为它们服务的包；本地关键词检索先测量再决定是否增加轻量索引。
- 已开始底层代码施工；真实用户数据与凭据仍不进入自动化测试。产品功能范围以实际验证和施工状态为准。

## 下一步如何定稿

先用公开/合成资料验证目标设立、行动/受阻、回看和修改决定的完整旅程；再评测新网页与现有目标的对照解读。书籍推荐先核对中文目录覆盖和个人化理由，尚无施工编号。每个弹性能力先过 G0–G3 研究与可丢弃原型，G4 形成正式施工决策卡并修订 05/06，再进入目标相关功能施工；实现后用 G5 限量试用验证长期效果。未通过则保留可靠底层、缩小或删去附加 AI 功能。R2 的25包缺少 Goal/Decision/CheckIn 正式任务，不能直接作为最终顺序。UI研究与功能验证并行，但导航在目标原型验证前不冻结。

## 调研事实与限制

既有代码风险是静态检查结果，未跑真实库迁移、性能或 AI 质量实测。竞品研究使用公开官方资料与有限第三方内容，没有 Get 实机账号体验，也未观看只取得摘要的视频。07–11所列研究是产品设计依据与推断，不是 FlowNote 的实测效果。`paddleAPI.txt` 为用户给定参考，凭据未写入文档。

# 分期施工与验收

本文件保留供GPT-5.6-Sol使用的T00–T11基础任务卡；完整R2施工顺序与补充规格以06为准。每次只做一张卡；完成测试、说明行为并形成可回滚提交后，再进入下一张。若任务必须更改已锁定的产品决策，停止该任务并说明冲突，不自行扩大范围。

## 1. 全局执行规则

- 先读本目录 README、技术方案对应小节和任务涉及源码。历史更新日志只提供背景，不作为已实现状态的唯一依据。
- 保留 React/Electron/TypeScript、JSON/Markdown 和坚果云，不引入账号、服务器、语音、向量数据库或全仓 UI 重写。
- 生产数据不作测试夹具；默认使用临时测试库和模型/HTTP 假响应。付费 API 实测只用用户明确选择的小样本。
- 每卡明确新增依赖及原因。锁定实际通过构建的版本，不顺手升级 Electron/React 等基础组件。
- 不运行当前 `package:win` 的 prune 流水线来“顺便验证”，因为它会改动依赖安装状态。打包流程在最终验收单独验证。
- 本轮文档没有提交代码。未来实施用独立 `codex/` 分支，每张卡一个目的明确的提交；不提交 API 示例中的凭据、真实笔记、构建产物或本机配置。
- 测试覆盖数据丢失、重试计费、引用正确性与兼容，而非给每个样式函数写镜像测试。

## 2. 依赖顺序

```text
T00 基线
  → T01 保存与时间 → T02 导入恢复 → T03 任务队列
  → T04 来源模型 → T05 OCR → T06 网页
  → T07 搜索 → T08 来源 UI → T09 问答
  → T10 Wiki/Dream 可靠性与成本 → T11 集成发布验收

Alpha后：T12–T21完整产品能力 → T22正式验收（详见06）
可选后置：T23 Android采集试验 → T24 鸿蒙试验
```

任务执行顺序以此为准。即使部分技术可以并行，Sol默认按任务依赖顺序执行，降低共享类型与数据管线冲突。T03 提前修复重试机制；T10 在新来源与引用已经稳定后调整 Wiki。

## 3. 首批任务卡

### T00｜冻结基线与最小测试入口

- 目标：知道哪些问题是旧问题，并能复现关键故障，不碰业务行为。
- 阅读：package.json、tsconfig、TROUBLESHOOTING、现有入口及数据层。
- 修改：新增适配当前 Node/Electron 工具链的 Vitest 测试配置、临时库夹具、模型与文件故障注入工具；增加独立 test/typecheck 脚本，不改变打包脚本。
- 交付：基线记录，包括 Git 提交、构建与类型检查实际结果、已知错误清单、测试命令。历史手册中的类型错误数量必须重新测量，不能照抄。
- 验收：npm run build；主进程/renderer 类型检查；基线测试可脱离真实 sync_dir 运行。既有错误单独记录，后续不得新增错误。
- 禁止：自动升级依赖、修遍所有旧类型错误、使用真实 API Key 运行测试。

### T01｜可靠保存、ID 与时间工具

- 目标：同一毫秒保存100条不覆盖；写入失败不损坏旧记录；异步结果不覆盖用户编辑。
- 修改边界：note-store、共享时间/指纹/原子写工具、必要调用点；加同机单实例保护。保持 notes API 兼容。
- 具体行为：数字 ID 单调分配＋排他创建；统一 created_at_ms 回退；同 Note 提交串行化；AI 结果按输入指纹补丁更新。
- 验收：固定 Date.now 连续保存100条，数量与内容一致；时钟回拨不覆盖；模拟替换失败旧记录完整；AI 等待期间用户更改正文/附件，新内容保留；旧13位 JSON 可读取。
- 交付限制：不迁移全部旧文件，不改变 category，不引入多端并发编辑协议。

### T02｜inbox 可恢复导入

- 目标：中途故障和重启不吞剩余内容，也不重复创建已保存笔记。
- 修改边界：inbox-store、inbox-watcher、导入回执与测试；沿用启动扫描及周期检查习惯。
- 具体行为：唯一批次快照、固定 block 标识、Note.capture_id、成功回执与启动恢复；全部保存成功后才归档快照。
- 验收：在第1/中间/最后一条前后注入异常；重启两次后笔记数量正确；两个相同文本块保留两条；LF/CRLF/CR/BOM/空白行通过；历史 processing.txt 恢复；云盘文件锁不导致删除。
- 回执规则：已导入 capture_id 的回执独立保留，删除笔记后重放旧采集包不能使其复活。若 Note 已写而回执未写，扫描 Note.capture_id 补建回执。
- 禁止：在 finally 删除未确认处理完成的输入；只用文本 hash 或 sleep 去重。

### T03｜统一任务与可核对的调用用量

- 目标：重试有限、重启可恢复、同一任务不被重复收费；修复旧分类器重试归零路径。
- 修改边界：新增本机 job-store/task-runner；LLM 客户端单次调用与兼容包装；分类器逐步接入；通知映射。
- 具体行为：实现技术方案状态机、inputHash 去重、并发与优先级、取消、本机 usage；区分模型返回空、网络失败和参数错误。
- 验收：401不循环；429按退避恢复；同任务自动尝试最多3次且重启不清零；并发不超过限制；分类重试失败进入可见失败态；AI 返回时输入已变化不覆盖用户编辑；没有 usage 时显示未知。
- 交付：任务列表最小 UI，可重试/取消/查看短错误；日志不含 Key、图片 base64 或完整个人笔记。
- 禁止：让旧客户端重试与新队列重试叠乘；无 jobId 的提交不确定状态自动无限重提。

补充T03验收：切换 sync_dir 后旧任务、搜索响应和远端OCR结果均不得落入新库；回到旧库后可恢复其已知任务。

### T04｜来源模型与统一采集保存

- 目标：先保存 Note/Source/附件，再排处理任务；原始资料与个人批注分开。
- 修改边界：共享类型、source-store、capture 服务/IPC、现有附件与输入区。
- 具体行为：落实 origin、source_ids、include_in_wiki、SourceRecord、SourceRef；新资料默认不自动纳入 Wiki；旧笔记行为保持。
- 提交顺序：先写原始附件与完整 Source，再写引用它的 Note；若中途失败记录未完成导入并可恢复，不能报告保存成功。失去引用的文件先标记，不自动删除。
- 验收：图片保存时断网仍有原图；批注与正文分离；重启后可见；source丢失/附件未同步时显示可恢复状态；旧附件可预览/打开；AI不能改用户文字。
- 禁止：首次升级自动上传全部旧附件；把所有收藏文章内容都写进 raw_content。

### T05｜PaddleOCR 与按需图片理解

- 前置：T03/T04。
- 修改边界：Paddle HTTP 适配器、提取服务、设置与图片状态；DeepSeek 多模态适配器单独函数。
- 具体行为：按用户样例接口提交、保存jobId、轮询、下载JSONL、解析多页文本；保存所需图片并改写链接；缓存结果；DeepSeek图片理解显式按钮触发。
- 验收：用假响应覆盖 pending/running/done/failed、401/429/5xx、响应丢失、结果下载失败、分页缺失、结果URL失效、超时继续查询；同图重复处理复用；用户修正OCR后默认不再请求；断点恢复不重提已知jobId。
- 真接口小样本：一张中文截图、一张旋转照片、一张表格；验证可识别字段与引用定位，不以3张图宣称总体准确率。首次测试关闭自动后台批量任务。
- 限制：默认非自动付费回退；不新增本地 Python/OCR 服务；不能硬编码示例 token。

### T06｜公开网页与手动正文

- 前置：T04；复用T03重试和状态。
- 修改边界：网页提取服务、Readability适配、存链接表单与详情。
- 具体行为：20秒超时、5次跳转、5MiB限制；正文、URL和批注分开；相同URL可打开已有或生成新快照。
- 验收：静态文章成功；乱码/无正文/404/超时有可理解错误；需登录页面可粘贴正文；恶意脚本不执行；非http与内网跳转拒绝；外部页面中的指令不改变AI任务。
- 禁止：引入登录Cookie、后台浏览器爬虫、自动采集评论、绕过登录或访问限制。

### T07｜全文索引、增量更新与中文召回

- 前置：T04–T06。
- 修改边界：MiniSearch适配、共享分词/分块、索引生命周期、search IPC；旧搜索接口可委托新服务，但返回形状保持兼容。
- 具体行为：索引笔记、来源、当前/封存Wiki；排除备份和答案；支持范围与分页；应用写入增量更新，外部同步定期核对。
- 验收：中文词、单字、英文、标签、标题、OCR文本、网页正文均可命中；用户编辑/删除后索引更新；临时读取失败不清空索引；索引损坏可重建；查询不触发API。
- 测试数据：1000和10000条合成笔记，中文/英文/长文混合，另加图片提取文本和封存Wiki。记录设备与语料体量；目标10000条热查询P95≤300ms，索引构建不能使输入UI长时间冻结。
- 性能未达标处理：先把建索引移到worker并批量更新；不直接改成远端数据库。目标是验收门槛而非现有承诺。

### T08｜来源查看与统一搜索界面

- 前置：T07。
- 修改边界：新搜索页、Source详情、Wiki定位与SourceRef resolver；保留现有主题和导航习惯。
- 具体行为：结果摘要/来源/日期，图片原图对照，段落定位，过期引用提示，Wiki当前/全部搜索。
- 验收：OCR-only命中不会被renderer的旧title/raw_content二次过滤掉；跨页打开位置正确；查询快速变化不显示旧请求结果；封存Wiki可打开；删除来源不跳错误条目。
- 特别注意：现有 NotesContext 会再次按 title/raw_content 过滤，不能只升级后端搜索而保留这一排除新来源的逻辑。

### T09｜带引用问答

- 前置：T03/T07/T08。
- 修改边界：knowledge服务、问答IPC、提示词与答案展示/保存；不改变默认普通搜索。
- 具体行为：前30候选、最多8片段/8000字符、问题改写或格式修复共享1次额外调用预算、来源白名单与原文quote校验、答案保存及过期状态。
- 验收：直接事实、多来源合并、同义问法、日期限定、无答案、冲突资料、伪造引用、来源更新/删除、超长问题、取消及重启；单次最多2次模型调用。
- 真接口评测：固定30题，包括10事实、5跨文档、5同义问法、5无答案、5冲突/时间范围。事实和跨文档问题人工可核对正确率目标≥90%；无答案题不编造；引用定位有效率100%。同义问法单列召回结果，不用漂亮答案掩盖漏召回。
- 禁止：整库塞上下文、捏造引用、自动联网补全、把历史AI答案重新当作原始证据。

### T10｜Wiki 批量合并与 Dream 成功状态

- 前置：T03/T04/T08；问答可已上线但本卡完成前不宣布首批完成。
- 修改边界：classifier-service、wiki-writer、wiki-store、dream-store/worker、provenance与少量状态UI。
- 具体行为：同Wiki串行、跨Wiki限并发、首条30秒或5条批次、长度预算与人工封存入口；来源清单和输出持久化后消费任务；写前比较Wiki指纹。
- Dream修复：失败释放锁但不推进成功游标；成功保存实际覆盖的笔记ID/输入指纹；新到或较早创建但较晚分类完成的笔记均留待后续；首次升级建立不自动付费重跑的历史基线；按真实周分组而非跨月复用“第几周”。
- 验收：同类笔记按时间合并且不重复；不同类别可并行；生成中封存/编辑不会被旧结果覆盖；保存失败不能消费任务；输出截断不覆盖Wiki；Dream空结果/失败/取消不漏掉后续待处理笔记。
- 成本对照：同样20条输入、同样初始Wiki与模型配置，比较每条立即合并和新批处理的调用次数、输入/输出token。必须报告实际值；无实测不宣称省了某个百分比。

补充T10验收：月底积压任务跨月执行仍写入入队时固定的笔记月份；Wiki在正式文件替换后、来源清单写入前崩溃，恢复只能补齐提交，不能重复合并/调用；Dream晚完成分类的旧笔记不被成功时间戳跳过，超过100条时未选入部分不标为已覆盖。

### T11｜副本演练、安装包与Alpha验收门槛

- 前置：T00–T10全部通过。
- 工作：用脱敏副本执行首次升级、索引重建、采集→OCR/网页→搜索→问答→Wiki全链；执行应用强退和重启；验证坚果云同步延迟/冲突可见。
- 构建：npm run build、类型检查与测试；隔离环境使用已确认的electron-builder流程，不先修改现有prune脚本。若打包基线失败，作为独立问题修复，不污染功能提交。
- 验收：开发模式与Windows安装包均可选择目录、显示原图/自定义字体、打开附件、读取旧库和恢复任务；第三方请求只在主进程，日志与安装包无用户凭据。
- 发布：新功能默认关闭，测试副本逐项开启；确认后备份真实库与配置，再启用。保留v2.9.0安装包和升级前备份。正式发布或Git推送按用户当时授权执行。
- 停止条件：存在未解决的丢数据、无限重试、错误引用跳转或恢复后重复导入问题，不进入主数据使用。

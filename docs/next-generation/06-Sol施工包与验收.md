## 2. Sol的权限边界与交付格式

允许Sol自主决定：文件内函数拆分、组件局部状态、类型名称的必要微调、测试假对象和符合当前锁文件/Node环境的依赖小版本。不得自主决定：改数据主库、改同步平台、加入语音/服务器/新付费供应商、取消Wiki/Dream、改变自动计费策略、绕过来源校验。

每个任务包分三个小提交：契约/存储与服务、界面接入、集成修正与测试。纯数据任务可以合并为一个提交。避免将不工作的半套类型传播到整个工程；如必须分提交，使用兼容包装让每个提交可构建。

每包开始：检查Git状态及implementation-status，读取规定文档与入口；说明当前实际状态和将完成的验收编号。每包结束必须写：改动范围、接口变化、测试命令及结果、未验证项、下一任务可依赖的事实、回滚点。

状态文件按任务记录：not_started/in_progress/verified/blocked、提交号、测试证据。blocked只能写具体外部条件，如缺真实设备或API鉴权；不能把尚未写的功能标为“已完成，后续优化”。此文档本身不预写任何verified记录。

## 3. 共用工程约定

### 3.1 真实入口与新增模块位置

- 现有共享类型：src/shared/types.ts；新实体可以拆到src/shared/contracts/并从公共入口导出，不把所有类型堆成一个巨文件。
- 现有服务在src/main/services，存储在src/main/store，IPC在src/main/ipc。新增Source/Job/Collection/Conversation/Insight/Artifact分别建模块，不能直接写进main/index.ts。
- preload/index.ts与其声明、IPC_CHANNELS、register-all.ts必须成套更新；renderer只看共享契约。
- 现有AppContext/PageIndex、App.renderPage和Sidebar为导航改造入口；当前设置页依赖数字4，T12必须一起处理。
- 当前NoteDetailDialog与NoteCard直接展示raw_content，T14才改成安全Markdown；现有MarkdownViewer可复用，但Wiki大纲/diff行为必须回归。
- 现有NotesContext在后端搜索后还按title/raw_content二次过滤，T08须移除不兼容新来源的那段过滤。

以上为已检查的真实入口；本文中的新模块名称是计划位置，不是声称仓库已有实现。

### 3.2 请求与事件

新增IPC用Result<T>，业务失败不靠throw字符串区分。每个请求带libraryId；取消/切库时递增renderer请求代次，晚返回的数据只能匹配当前库/代次才更新UI。所有任务事件包含libraryId、jobId、targetId、state，只有当前订阅者响应。

更新保存使用expectedRevision；AI应用使用输入hash。revision用于并发写保护，不等于内容hash；只修改favorite也增加revision，但不使OCR/问答的内容缓存无理由失效。

renderer卸载时解除事件订阅；组件重复渲染不得重复注册任务监听。所有文件写入只在主进程服务执行；SourceRef定位由resolver负责，不允许组件拼绝对路径。

### 3.3 复用的AI证据协议

模型只看到本次S1…Sn编号、资料类型、标题、实际片段。返回中的编号必须来自本次输入；quote必须在对应片段中。关联有两个有效来源，反思有当前原句，成果中引用对应材料。格式修复不允许凭空增加新材料。

失败可以展示本地检索结果和“没有生成可靠答案”，不能把无引用的自由回答标为已核验。问题改写、正常生成、格式修复与网络重试共用单动作最多2次实际模型HTTP请求预算，详见05第9节；预算按actionId持久化并由所有子任务共享，发出前扣减。自动日预算也包含失败请求，避免只计成功调用。

### 3.4 测试夹具与执行命令

T00建立fixtures工厂，测试只写临时目录。最少夹具：旧版Note、中文/英文Note、同文本不同ID、多个附件、缺失Source、改变正文的同ID、封存Wiki、跨月时间、外部网页、派生笔记、含恶意指令的资料。

API假服务可注入：成功、空文本、格式错、伪造引用、401、429含Retry-After、500、超时、请求成功但响应丢失、轮询继续、半文件。文件层故障可在写临时文件、替换、写回执、写meta指针处注入。

T00固定脚本名为npm run typecheck、npm run test:run；保留npm run build。typecheck调用当前Node/renderer两个tsconfig的noEmit检查；若composite配置需专用检查配置，可新增不产物的tsconfig.typecheck文件。Vitest选当前工具链兼容版本并锁定，不要求预先升级Electron。

React交互测试用Vitest＋Testing Library；原生安装包/中文IME用人工步骤表。测试用例优先断言用户可见结果、持久化结果和调用次数，不以组件内部状态名作为主要验收。
